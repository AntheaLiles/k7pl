**Status:** triage notes only; not a ratified classification and not permission to alter any source statement.

**Baseline:** source snapshot `20a228f137f507aac9b3e8c9f2e1776f29fa635a`. The mechanical inventory is being reviewed in [PR #81](https://github.com/AntheaLiles/k7pl/pull/81). This note records high-risk classification cases discovered while reading statement bodies and proof sketches. No source statement has been edited.

## Review principle

The old `status` value is not a reliable proxy for all target dimensions. In particular, a block can combine multiple claims with different epistemic states; a proof-sketch slot is not a machine-checked proof; and a result's logical role (theorem, lemma, corollary, proposition) is not its epistemic state. All candidate mappings below require review against the full surrounding context and dependencies.

## Cross-cutting controls

1. Do not map legacy `status = theoreme` directly to epistemic state `established`.
2. Do not map the presence of `:::proofsketch` to a proof-completion flag or to a Lean-verified proof.
3. Preserve local assumptions, side conditions, cited statement labels, and explicit uncertainty during the first migration.
4. Keep the current `level` as historical metadata until a separate scope classification is reviewed.
5. Separate the initial lossless migration from any editorial splitting or rewriting of compound claims.
6. Treat each candidate above as a review flag, not a final ontology assignment.
