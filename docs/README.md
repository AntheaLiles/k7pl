# K7PL Documentation

Documentation is organized around the information a reader needs, rather than around the historical production process.

**Document version:** 1.0.0  
**Last updated:** 2026-10-06  
**Audience:** researchers, reviewers, contributors, and readers who need to understand the current K7PL project.

## Understand K7PL

Start with:

- [Architecture](ARCHITECTURE.md): project structure, conceptual layers, and relationships between specification, formalisation, implementation, proofs, and tests.
- [Research](RESEARCH.md): scientific problem, hypothesis, object, expected contributions, and validation strategy.
- [Specification](../spec/): the normative language specification.

## Assess the current state

- [Status](STATUS.md): CI-generated factual project state. Do not edit this file manually.
- [Assurance](ASSURANCE.md): scientific assurance case, evidence, claims, traceability, and limitations.
- [Security and supply-chain assurance](security/README.md): OpenSSF audit, roadmap, threat model, and human actions. Distinct from the scientific assurance case above.

## Work on K7PL

- [CONTRIBUTING.md](../CONTRIBUTING.md): contribution workflow and repository rules.
- [src/](../src/): Lean implementation.
- [tests/](../tests/): executable tests.

## Review K7PL

## Historical and legacy material

The existing directories suivi/, relectures/, methode/, recherche/, bibliographie/, journal/, and historique/ are intentionally retained in place.

The working entry point of that tree is [`suivi/TABLEAU-DE-BORD.md`](suivi/TABLEAU-DE-BORD.md) (state of the manuscript and what remains), with [`suivi/RESTE-A-FAIRE.md`](suivi/RESTE-A-FAIRE.md) (open items) and [`suivi/DECISIONS.md`](suivi/DECISIONS.md) (decided, applied "to be ratified", genuinely pending). The session journal is in [`journal/`](journal/). The detailed analyses, set against the manuscript, of each element the author has to decide are indexed in [`recherche/analyses-decisions/`](recherche/analyses-decisions/README.md).

A later migration programme will classify, rewrite, cross-reference, and relocate their relevant material. No current document should silently become normative merely because it is old or detailed.

See also [archives/](../archives/) for frozen historical implementation material.

## Documentation model

The current human navigation path is:

README.md → ARCHITECTURE.md → RESEARCH.md / spec/ → ASSURANCE.md → STATUS.md

This path is an entry point, not a replacement for the normative specification or the detailed evidence held in the legacy material.
