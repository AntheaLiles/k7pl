# K7PL Documentation

Documentation is organized around the information a reader needs, rather than around the historical production process.

**Document version:** 1.0.0  
**Last updated:** 2026-10-13  
**Audience:** researchers, reviewers, contributors, and readers who need to understand the current K7PL project.

## Understand K7PL

Start with:

- [Architecture](ARCHITECTURE.md): project structure, conceptual layers, and relationships between specification, formalisation, implementation, proofs, and tests.
- [Research](RESEARCH.md): scientific problem, hypothesis, object, expected contributions, and validation strategy.
- [Specification](../spec/): the normative language specification.
- [Interactive exploration](tracking/INTERACTIVE-EXPLORATION.md): architecture and current prototype scope.
- [Interactive exploration plan](tracking/INTERACTIVE-EXPLORATION-PLAN.md): user stories, acceptance criteria, implementation status and validation gates.
- [Interactive exploration inventory](tracking/INTERACTIVE-EXPLORATION-INVENTORY.md): canonical sources, generators, validators and current limits.
- [Navigation prototype](tracking/NAVIGATION-PROTOTYPE.md): implementation contract, all-page coverage and deployment/usage limits.
- [Navigation semantic model](tracking/NAVIGATION-SEMANTIC-MODEL.md): allowed relation types, provenance and epistemic-status boundaries.
- [Navigation graph implementation](../scripts/ci/navigation_graph/README.md): generated HTML graph, node/edge contracts, build commands and validation limits.
- [Proof visualization roadmap](tracking/PROOF-VISUALIZATION-ROADMAP.md): Paperproof extraction workspace, static site views, source provenance and remaining extension gates.
- [Proof visualization coverage matrix](tracking/PROOF-VISUALIZATION-COVERAGE.md): evidence-based coverage by proof form, tactic, context, data provenance, and HTML/PDF integration.
- [Proof visualization human review](tracking/PROOF-VISUALIZATION-HUMAN-REVIEW.md): browser/PDF inspection checklist separate from automated CI evidence.

## Historical and legacy material

The documentation tree has been reorganized into explicit epistemic areas: `tracking/`, `history/`, `peer-review/`, `research/`, `method/`, `bibliography/`, `migration/`, `archives/`, and `security/`. No current document should silently become normative merely because it is old or detailed.

The completed coherence-review workstream is preserved as a dated record in [history/2026-10-09-coherence-review.md](history/2026-10-09-coherence-review.md); its checklist is historical evidence, not an active task list. The closed figure-sheet audit and TikZ proof of concept are likewise retained under `history/`, not as active tracking. The OpenSSF checklist and initial remediation plan are likewise retained under history/; use the active security roadmap and human-action register for current work.

See also [archives/](archives/) for frozen historical implementation material.

See [migration/](migration/README.md) for the controlled migration register and its execution state.

The interactive exploration project is tracked in [tracking/INTERACTIVE-EXPLORATION-PLAN.md](tracking/INTERACTIVE-EXPLORATION-PLAN.md).

## Documentation model

The current human navigation path is:

Repository `README.md` → `docs/ARCHITECTURE.md` → `docs/RESEARCH.md` / `spec/` → `docs/ASSURANCE.md` → `docs/STATUS.md`

This path is an entry point, not a replacement for the normative specification or the detailed evidence held in the supporting registers.
