# K7PL Documentation

Documentation is organized around the information a reader needs, rather than around the historical production process.

**Document version:** 1.0.0  
**Last updated:** 2026-10-10  
**Audience:** researchers, reviewers, contributors, and readers who need to understand the current K7PL project.

## Understand K7PL

Start with:

- [Architecture](ARCHITECTURE.md): project structure, conceptual layers, and relationships between specification, formalisation, implementation, proofs, and tests.
- [Research](RESEARCH.md): scientific problem, hypothesis, object, expected contributions, and validation strategy.
- [Specification](../spec/): the normative language specification.
- [Interactive exploration](tracking/INTERACTIVE-EXPLORATION.md): proposed interactive presentation and knowledge navigation layer.

## Assess the current state

- [OpenSSF / supply-chain status](security/OPENSSF-ROADMAP.md): current remediation gates, BadgeApp preparation and unresolved external validations.
- [Human actions](security/ACTIONS-HUMAINES.md): ordered procedure for maintainer-only decisions, settings and publication.
- [Status](STATUS.md): CI-generated factual project state. Do not edit this file manually.
- [Assurance](ASSURANCE.md): scientific assurance case, evidence, claims, traceability, and limitations.
- [Security and supply-chain assurance](security/README.md): OpenSSF audit, roadmap, threat model, and human actions. Distinct from the scientific assurance case above.

## Historical and legacy material

The documentation tree has been reorganized into explicit epistemic areas: `tracking/`, `history/`, `peer-review/`, `research/`, `method/`, `bibliography/`, `migration/`, `archives/`, and `security/`. No current document should silently become normative merely because it is old or detailed.

The completed coherence-review workstream is preserved as a dated record in [history/2026-10-09-coherence-review.md](history/2026-10-09-coherence-review.md); its checklist is historical evidence, not an active task list. The OpenSSF checklist and initial remediation plan are likewise retained under history/; use the active security roadmap and human-action register for current work.

See also [archives/](archives/) for frozen historical implementation material.

See [migration/](migration/README.md) for the controlled migration register and its execution state.

The interactive exploration project is tracked in [tracking/INTERACTIVE-EXPLORATION-PLAN.md](tracking/INTERACTIVE-EXPLORATION-PLAN.md).

## Documentation model

The current human navigation path is:

Repository `README.md` → `docs/ARCHITECTURE.md` → `docs/RESEARCH.md` / `spec/` → `docs/ASSURANCE.md` → `docs/STATUS.md`

This path is an entry point, not a replacement for the normative specification or the detailed evidence held in the supporting registers.
