# Bibliography

This page is the successor of `docs/bibliography/`
(deleted in the security, decisions, docs-root and
bibliography closing of 2026-10-25). It states how the
bibliography data is organised, what its rules are, and
what was abandoned — it does not list the 254 entries,
which live in the data file below.

## Data files (not prose)

- [references.json](references.json) — 254 entries, the
  bibliographic metadata of the works the specification
  cites. The full Zotero library (abstracts, local file
  paths, uncited entries) stays out of the repository;
  only cited metadata is kept, formatted following ISO
  690 (numeric), roughly as the manuscript obtained it
  from `biblatex` (`bibstyle=iso-numeric`). This file is
  data: do not edit it as prose. It is the input to
  `tools/SpecBib.lean` (generated by
  `scripts/biblio/biblio.py lean`, freshness checked by
  `scripts/ci/test_specbib_fresh.py`) and to the
  semantic-graph builder
  (`scripts/ci/build_semantic_graph.py`), which fails
  on an unresolved bibliography key. In the published
  wiki export it appears under `assets/`, not as a
  page.
- [bibliography-decisions.json](bibliography-decisions.json) —
  dated, reasoned decisions about bibliography keys:
  keys maintained although uncited (each entry is a
  decision, dated and reasoned; the pass check reports
  such keys without failing, but fails on any uncited
  key not in this list — the difference between a
  decision and a silence), keys lifted, a status note
  of 2026-08-10 on the bibliography references, keys
  cited without a PDF, and erroneous metadata. No
  script reads this file; it is the decision record
  for the keys it names, and its reasons must not be
  silently dropped when a key is changed.

## Rules

- **Cite only what is in the data file.** A citation
  key used in `spec/` must resolve in
  `references.json`; the semantic-graph builder fails
  otherwise.
- **An uncited key is either removed or decided.**
  Keeping an uncited key requires a dated, reasoned
  entry in the decisions file; silence is not a
  decision. This rule exists because a reference once
  crossed twenty-five versions without employment
  unnoticed.
- **No bibliography change without a primary source.**
  From the consolidated PR-03 review (finding R-10,
  carried in the roadmap): do not modify the data
  file except with a DOI or primary source in hand,
  and distinguish a literature result from a result
  established for K7PL. The graded-system chapter's
  decidability and normalisation citation, and the
  Abel / Moon graded-modal-dependent-type-theory
  attribution, are to be checked against their primary
  sources before any change.
- **Regenerate after every change.** After editing
  `references.json`, regenerate `tools/SpecBib.lean`
  with `python3 scripts/biblio/biblio.py lean
  wiki/references.json tools/SpecBib.lean`; the
  freshness test fails otherwise. A notice added to
  the data file without regenerating is an error, not
  a pending task.

## What was abandoned, and why

- **Keys to add to the collection** (`a-ajouter-collection.md`,
  2026-09-02): absorbed — the complete collection
  export of 2026-09-03 made the request moot, with
  all 49 keys verified key by key in the collection
  file (the 49th under a changed key, `THEOCHARIS`,
  not an absence). Nothing remains to do; the file is
  a trace, surviving in git history.
- **Loading and naming sourcing lists**
  (`a-charger.md`, `a-sourcer-nommage.md`): historical
  redirects whose sole entry point was already the
  core-vocabulary historical inventory in
  `docs/research/` (research lot). They carried no
  current obligation; the naming sourcing list
  explicitly states it must not be resumed as a
  current bibliographic obligation, and its eleven
  references from the Oliveira et al. review were
  recorded as not blocking the naming arc.
- **Corpus-gap sourcing** (`a-sourcer-manques.md`,
  2026-08-31): dated verification state (online
  checks of that day, other entries given from
  memory with their reserve, and an explicit banner
  that it does not govern current availability).
  Corpus gaps themselves belonged to the research lot
  (`docs/research/manques.md`, closed with the research lot
  of 2026-10-25 as a historical pointer, with its reason
  traced in the migration matrix); this sourcing sheet
  must not be quoted as current availability.
- **Reference state after the two-file BibTeX switch**
  (`a-traiter.md`, 2026-09-03): resolved state — the
  two points owed to the owner were settled that
  evening, with counts recorded (4,325 readable
  entries, 4,290 reachable PDFs, zero cited keys with
  another entry's abstract). Nothing remains open.
- **PR-02 verification records** (`verifications-pr02.md`,
  2026-10-01, and `verifications-pr02-archive-pr10.md`,
  records 3–5, PR #10 archive, translated
  2026-10-14): the verified findings for cards
  BIB-03, BIB-04, BIB-06, BIB-07, BIB-08, BIB-09,
  BIB-10, BIB-18 and BIB-20 are carried by the
  roadmap's 65-card list (tracking closing); the
  archive records are explicitly non-normative,
  unreviewed and unratified, and their closures are
  **not** carried by the card register on `main` —
  the archive file's own editorial notes list the
  discrepancies (including a manuscript correction
  claimed for BLOQ-12 that is false on `main`, and
  BIB-17 recorded closed in the archive but open in
  the register). Neither file's "State" column is
  current state; do not cite it as such.
